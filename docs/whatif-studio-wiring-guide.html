Field note

Verification history

What the verification pass against source caught, and what's since changed as a result — kept here as a record rather than deleted, since it's the reason to check source instead of only reading docs.

  1. ✓ fixed 2026-08-26 The biggest one: "Use for What-If Analysis" and 🗑️ Delete (Experimentation & Model Selection) were not part of what_if.py / what_if_service.py at all, even though flow.md §4b grouped them with the What-If backend surface. They lived in a fully separate router, backend/app/api/routes/overview.py, backed by overview_service.py, called via api/overview.ts — not api/whatIf.ts. That router has since been deleted; all four experiment endpoints now live in what_if.py — see Table 04.
  2. PI Tag Mapping's save function is named commit_mapping in what_if_service.py — not commit_pi_mapping, which is the name you'd guess from the sheet. (Still true — unaffected by the above.)
  3. commit_mapping is the one commit_* function that isn't a pure pass-through write: it runs wizard.normalize_pi_df() on the edited rows before persisting them.
  4. The four embedded Model Development phases (Connect Data / Data Health / AI Feature Discovery / Build Model) never call api/whatIf.ts at all — they use their own pre-existing domain files (datasets.ts, preprocess.ts, featureSelection.ts, training.ts), since those pages are reused verbatim, unmodified, from the standalone pipeline. Easy to assume everything under What-If Setup goes through one API file — it doesn't.
  5. ModelConfigTab.tsx's "Configure Model" / "Define Formula" actions chain two calls, not one: they save via commitModelMapping first (on its success callback), then navigate to the target phase — the mapping is always persisted before Feature Discovery or the Formula Editor opens.
  6. ✓ fixed 2026-08-26 A fully separate dead vertical slice was also found and removed in the same pass: predict.py/predict_service.py/schemas/predict.py/api/predict.ts had zero live callers anywhere (its only frontend caller, Predict/PredictPage.tsx, had already been deleted). Along with it, four reused pipeline pages (UploadPage, PreprocessPage, FinalApply, TrainPage) each had a dead navigate('/preprocess'|'/feature-selection'|'/train'|'/predict') fallback pointing at standalone routes that no longer exist in routes.tsx — their onContinue prop is now required instead of optional-with-fallback.
